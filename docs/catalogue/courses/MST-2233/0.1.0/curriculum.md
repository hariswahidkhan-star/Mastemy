## Learning outcomes

1. Explain the design thinking mindset and its five modes
2. Conduct user research through interviews, observation and empathy mapping
3. Define problems with point-of-view statements and journey maps
4. Ideate, prototype and run usability tests to learn fast
5. Apply core usability and accessibility heuristics to interfaces
6. Measure UX outcomes and communicate findings to stakeholders

## What this course assesses / does not assess

- Assesses: knowledge and applied reasoning on every in-scope outcome, using single-answer MCQ and multiple-answer selection only.
- Does not assess: Assesses knowledge and applied reasoning through selection items; does not assess hands-on performance.

## Sample items (original, draft, unreviewed)

**MST-2233-Q0001** (single-answer, Select ONE) In design thinking, what is the main goal of the Empathise mode?

- A. To understand users' real needs and context before defining solutions **(key)**  
  _Rationale:_ Correct: empathy work grounds the whole process in genuine user needs.
- B. To finalise the colour palette  
  _Rationale:_ Visual decisions come much later, if at all, in this mode.
- C. To write the production code  
  _Rationale:_ Building comes after problems are framed and tested.
- D. To choose the project budget  
  _Rationale:_ Budgeting is a management task, not the purpose of empathising.

**MST-2233-Q0002** (multiple-answer, Select TWO) Which TWO are good practices when interviewing users? (Select TWO.)

- A. Ask open, non-leading questions **(key)**  
  _Rationale:_ Correct: open questions surface real behaviour rather than confirming assumptions.
- B. Listen more than you talk and probe for stories **(key)**  
  _Rationale:_ Correct: concrete stories reveal needs better than opinions.
- C. Suggest the answer you hope to hear  
  _Rationale:_ Leading questions bias the data.
- D. Only ask yes/no questions  
  _Rationale:_ Closed questions limit the insight you can gather.

**MST-2233-Q0003** (single-answer, Select ONE) A usability test shows users repeatedly miss a key button. What does this most directly indicate?

- A. A usability problem to fix, regardless of how the screen looks **(key)**  
  _Rationale:_ Correct: observed task failure is direct evidence of a usability issue.
- B. That the users are not smart enough  
  _Rationale:_ UX blames the design, not the user, for consistent failures.
- C. That the colour scheme is perfect  
  _Rationale:_ Missing a button is a usability failure, not a win.
- D. That no further testing is needed  
  _Rationale:_ Findings should drive iteration and re-testing.
