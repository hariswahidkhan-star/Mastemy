## Learning outcomes

1. Describe the Product Owner accountability and value focus in Scrum
2. Apply product vision, goals and backlog management
3. Evaluate ordering and refinement of the Product Backlog for value
4. Analyse stakeholder collaboration and release decisions

## Integrative case

A Product Owner for a new app faces competing stakeholder demands and a backlog ordered by politics: craft a clear product goal, re-order the backlog by value and risk, refine items into releasable slices, and decide when to ship value.

## Sample items (original, draft, unreviewed)

**MST-0139-Q0001** (single-answer, Select ONE) Several senior stakeholders each insist their feature goes first. The Product Owner should order the Product Backlog primarily by:

- A. Value, risk and dependencies toward the product goal **(key)**  
  _Rationale:_ Correct: the PO orders the backlog to maximise value, not by seniority.
- B. Whichever stakeholder has the highest title  
  _Rationale:_ Title does not determine value.
- C. The order requests arrived  
  _Rationale:_ Arrival order does not reflect value.
- D. Alphabetical feature name  
  _Rationale:_ Alphabetical order ignores value.

**MST-0139-Q0002** (single-answer, Select ONE) A Product Owner says value can only be delivered when the whole project is finished. This view conflicts with Scrum because Scrum aims to:

- A. Deliver a valuable, usable Increment at least every Sprint **(key)**  
  _Rationale:_ Correct: Scrum delivers value incrementally, not only at the end.
- B. Avoid delivering anything until the end  
  _Rationale:_ That contradicts incremental delivery.
- C. Release only once per year by rule  
  _Rationale:_ Scrum sets no such annual rule.
- D. Prevent stakeholder feedback  
  _Rationale:_ Scrum actively seeks frequent feedback.

**MST-0139-Q0003** (multiple-answer, Select TWO) Which TWO are genuine accountabilities of the Product Owner? (Select TWO)

- A. Ordering the Product Backlog to maximise value **(key)**  
  _Rationale:_ Correct: the PO orders the backlog.
- B. Clearly expressing Product Backlog items **(key)**  
  _Rationale:_ Correct: the PO ensures the backlog is clear and transparent.
- C. Writing all the code personally  
  _Rationale:_ Developers build the product, not the PO.
- D. Running the team's performance appraisals  
  _Rationale:_ That is not a Scrum accountability.
- E. Approving every line of the Definition of Done alone  
  _Rationale:_ The Definition of Done is owned by the Scrum Team, not the PO alone.
