## Learning outcomes

1. Describe the categories and capabilities of AI coding assistants
2. Define weighted, measurable criteria for tool selection
3. Build a task suite that represents real team work
4. Execute benchmarks fairly and record evidence
5. Weigh total cost, data handling and compliance in selection
6. Synthesise a recommendation and a rollout plan

## What this course assesses / does not assess

- Assesses: knowledge and applied reasoning on every in-scope outcome, using single-answer MCQ and multiple-answer selection only.
- Does not assess: Assesses knowledge and applied reasoning through selection items; does not assess hands-on performance.

## Integrative case

An engineering org must choose an AI coding assistant for 200 developers. Define evaluation criteria, build a representative task suite, run a fair benchmark, weigh cost, security and workflow fit, and present a defensible recommendation to a buying committee.

## Sample items (original, draft, unreviewed)

**MST-0572-Q0001** (single-answer, Select ONE) A team benchmarks three assistants but each on a different set of tasks. What is the main flaw?

- A. The comparison is not controlled, so differences cannot be attributed to the tools **(key)**  
  _Rationale:_ Correct: varying tasks confounds the comparison.
- B. Three tools is too few to compare  
  _Rationale:_ The count is not the core issue.
- C. Benchmarks should never use real tasks  
  _Rationale:_ Representative tasks are desirable.
- D. Cost should be the only criterion  
  _Rationale:_ Cost alone ignores capability and fit.

**MST-0572-Q0002** (multiple-answer, Select TWO) Which TWO factors belong in total cost of ownership for an AI coding assistant, beyond the per-seat price? (Select TWO.)

- A. Human review and rework time for generated code **(key)**  
  _Rationale:_ Correct: review overhead is a real recurring cost.
- B. Security, data-handling and compliance effort **(key)**  
  _Rationale:_ Correct: governance work is part of the true cost.
- C. The number of GitHub stars the vendor has  
  _Rationale:_ Popularity is not a cost factor.
- D. The colour of the editor theme  
  _Rationale:_ Irrelevant to cost.

**MST-0572-Q0003** (single-answer, Select ONE) Before committing 200 developers to one tool, what is the soundest next step after benchmarking?

- A. Run a time-boxed pilot with a representative group and success criteria **(key)**  
  _Rationale:_ Correct: a pilot validates the choice at low risk.
- B. Sign a three-year contract immediately  
  _Rationale:_ That commits before evidence from real use.
- C. Let each developer pick any tool with no evaluation  
  _Rationale:_ That abandons governance and comparability.
- D. Choose the cheapest option regardless of fit  
  _Rationale:_ Cost alone ignores effectiveness.
