## Learning outcomes

1. Explain design thinking, its mindsets and when to use it
2. Empathise with users and frame problems from their needs
3. Define actionable problem statements and point-of-view
4. Ideate a range of solutions and select promising concepts
5. Prototype and test ideas to learn quickly and iterate

## What this course assesses / does not assess

- Assesses: knowledge and applied reasoning on every in-scope outcome, using single-answer MCQ and multiple-answer selection only.
- Does not assess: Assesses knowledge and applied reasoning through selection items; does not assess hands-on performance.

## Integrative case

A university's student services team faces falling satisfaction with its help desk. Run a design-thinking cycle: gather user insight, reframe the problem as a point-of-view statement, generate and select ideas, build a low-fidelity prototype of a new service, and plan a test to validate it with real students.

## Sample items (original, draft, unreviewed)

**MST-1758-Q0001** (single-answer, Select ONE) What is the main purpose of the Define phase in design thinking?

- A. To frame a clear, user-centred problem statement to solve **(key)**  
  _Rationale:_ Correct: Define synthesises research into an actionable problem framing.
- B. To build the final product  
  _Rationale:_ That is far later; Define precedes ideation.
- C. To choose the project budget  
  _Rationale:_ Budgeting is not the purpose of Define.
- D. To write the marketing plan  
  _Rationale:_ Marketing is outside the design-thinking cycle here.

**MST-1758-Q0002** (multiple-answer, Select TWO) Which TWO practices make a prototype useful for learning early? (Select TWO.)

- A. Keep it low-fidelity so it is fast and cheap to change **(key)**  
  _Rationale:_ Correct: low fidelity lets you iterate before over-investing.
- B. Test it with real users and observe their behaviour **(key)**  
  _Rationale:_ Correct: real user testing reveals what actually works.
- C. Perfect every visual detail before showing anyone  
  _Rationale:_ Polish slows learning and discourages change.
- D. Only ask users whether they like it  
  _Rationale:_ Observing behaviour beats opinion-only feedback.

**MST-1758-Q0003** (single-answer, Select ONE) During a brainstorm, a team keeps critiquing ideas as they are suggested. Why is this a problem?

- A. Early judgement suppresses the volume and range of ideas **(key)**  
  _Rationale:_ Correct: divergent thinking needs judgement deferred to generate options.
- B. Critique is never useful in design thinking  
  _Rationale:_ Critique is valuable later, in the converging step.
- C. It makes the session too long  
  _Rationale:_ The issue is idea suppression, not length.
- D. It skips the empathy phase  
  _Rationale:_ The phase is ideation; the problem is premature judgement.
