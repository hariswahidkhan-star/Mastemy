## Learning outcomes

1. Explain the consulting lifecycle and scope an engagement
2. Structure ambiguous problems with issue trees
3. Drive analysis with prioritised, testable hypotheses
4. Gather evidence and synthesise it into insight
5. Build a top-down, decision-ready recommendation
6. Deliver recommendations and support real impact

## What this course assesses / does not assess

- Assesses: knowledge and applied reasoning on every in-scope outcome, using single-answer MCQ and multiple-answer selection only.
- Does not assess: Assesses knowledge and applied reasoning through selection items; does not assess hands-on performance.

## Integrative case

A client says 'our profits are falling and we don't know why'. Scope the engagement, structure the problem with a MECE issue tree, form prioritised hypotheses, gather and synthesise evidence, and build a top-down recommendation you can defend to a hostile steering committee.

## Sample items (original, draft, unreviewed)

**MST-1097-Q0001** (single-answer, Select ONE) A client hands you a solution to implement, but the symptom suggests a different root problem. What should you do first?

- A. Define the real problem before committing to the handed-down solution **(key)**  
  _Rationale:_ Correct: solving the right problem is the consultant's first job.
- B. Implement exactly what was requested  
  _Rationale:_ That risks solving the wrong problem.
- C. Start gathering all available data immediately  
  _Rationale:_ Analysis without a defined problem wastes effort.
- D. Present a recommendation on day one  
  _Rationale:_ A recommendation before problem definition is premature.

**MST-1097-Q0002** (multiple-answer, Select TWO) Which TWO properties should an issue tree have? (Select TWO.)

- A. Mutually exclusive branches **(key)**  
  _Rationale:_ Correct: MECE requires no overlap between branches.
- B. Collectively exhaustive coverage **(key)**  
  _Rationale:_ Correct: MECE requires the branches to cover the whole problem.
- C. As many overlapping branches as possible  
  _Rationale:_ Overlap breaks the 'mutually exclusive' property.
- D. A single branch leading straight to your preferred answer  
  _Rationale:_ That is confirmation bias, not structuring.

**MST-1097-Q0003** (single-answer, Select ONE) When building a decision-ready recommendation, the pyramid principle says you should:

- A. State the recommendation first, then support it with grouped arguments **(key)**  
  _Rationale:_ Correct: lead with the answer, then the supporting logic.
- B. Walk through all the analysis before revealing the answer  
  _Rationale:_ That buries the decision the client needs.
- C. Avoid stating a clear recommendation  
  _Rationale:_ A consultant must take a clear position.
- D. Order slides by how long each analysis took  
  _Rationale:_ Effort is irrelevant to the audience's decision.
