## Learning outcomes

1. Draft and refine replies with Gemini in Gmail
2. Summarise long threads into key points
3. Extract action items and owners from email
4. Adjust tone, formality and length of drafts
5. Verify and edit AI output before sending
6. Apply privacy and responsible-use practices

## What this course assesses / does not assess

- Assesses: knowledge and applied reasoning on every in-scope outcome, using single-answer MCQ and multiple-answer selection only.
- Does not assess: Selection items assess knowledge and applied reasoning only; they do not assess hands-on performance in the product, which is taught through instructor-built walkthroughs.

## Sample items (original, draft, unreviewed)

**MST-0730-Q0001** (single-answer, Select ONE) What should you always do with a Gemini-generated reply before it goes out?

- A. Read and verify it for accuracy and intent **(key)**  
  _Rationale:_ Correct: generated replies must be reviewed before sending.
- B. Send it immediately to save time  
  _Rationale:_ Sending unread risks errors and misstatements.
- C. Forward it to everyone in your contacts  
  _Rationale:_ That is unrelated and inappropriate.
- D. Delete the original thread  
  _Rationale:_ Deleting context does not improve the reply.

**MST-0730-Q0002** (single-answer, Select ONE) Which task is Gemini in Gmail best suited to when facing a 25-message thread?

- A. Summarising the thread into key points **(key)**  
  _Rationale:_ Correct: thread summarisation condenses long conversations into key points.
- B. Permanently deleting the oldest messages  
  _Rationale:_ That is not a Gemini summarisation task.
- C. Changing the account password  
  _Rationale:_ Unrelated to summarisation.
- D. Blocking the sender  
  _Rationale:_ Blocking is a moderation action, not summarisation.

**MST-0730-Q0003** (multiple-answer, Select TWO) Which TWO checks matter when Gemini extracts action items from a thread? (Select TWO.)

- A. Confirm each task is attributed to the correct owner **(key)**  
  _Rationale:_ Correct: misattribution is a common extraction error.
- B. Verify dates and commitments against the original messages **(key)**  
  _Rationale:_ Correct: extracted details must be checked against the source.
- C. Assume every extracted task is final  
  _Rationale:_ Extraction can be wrong and needs review.
- D. Send the list before reading it  
  _Rationale:_ Unreviewed output should not be sent.
