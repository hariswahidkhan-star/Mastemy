## Learning outcomes

1. Describe how UX practices integrate with Scrum
2. Apply user research, hypotheses and experiments within Sprints
3. Evaluate outcome-focused design and measuring user value
4. Analyse collaboration between designers, developers and Product Owners

- Assesses: knowledge and applied reasoning on every in-scope outcome, using single-answer MCQ and multiple-answer selection only.
- Does not assess: Knowledge-practice forms use MCQ/MR only; official item formats not reproducible in this format are listed in the exam-version record.

## Sample items (original, draft, unreviewed)

**MST-0144-Q0001** (single-answer, Select ONE) A team wants to add a feature because an executive likes it, with no user evidence. A Scrum-with-UX approach would first:

- A. Frame it as a hypothesis and run a small experiment to test the assumption **(key)**  
  _Rationale:_ Correct: assumptions are validated with experiments before large investment.
- B. Build the full feature immediately  
  _Rationale:_ Large investment before validation is risky.
- C. Reject all executive input permanently  
  _Rationale:_ Input is welcome, but it is tested, not blindly built.
- D. Skip measuring whether users benefit  
  _Rationale:_ Measuring outcomes is central to the approach.

**MST-0144-Q0002** (single-answer, Select ONE) Integrating UX with Scrum means UX work should primarily happen:

- A. Within the Sprints, collaboratively and iteratively **(key)**  
  _Rationale:_ Correct: UX is integrated into the cadence, not a separate up-front phase.
- B. Entirely before any development starts  
  _Rationale:_ A big up-front phase contradicts the approach.
- C. Only after the product ships  
  _Rationale:_ Late UX misses the chance to shape the product.
- D. By a separate team that never meets Developers  
  _Rationale:_ Collaboration is essential.

**MST-0144-Q0003** (multiple-answer, Select TWO) Which TWO signals indicate a team is genuinely outcome-focused in Scrum with UX? (Select TWO)

- A. It measures whether users' problems are actually solved **(key)**  
  _Rationale:_ Correct: measuring user outcomes shows outcome focus.
- B. It validates assumptions with small experiments **(key)**  
  _Rationale:_ Correct: experimentation reflects an outcome mindset.
- C. It counts features shipped as its main success metric  
  _Rationale:_ Feature count is output, not outcome.
- D. It avoids ever talking to users  
  _Rationale:_ Avoiding users undermines outcome focus.
- E. It locks the design before any feedback  
  _Rationale:_ Locking out feedback is not outcome-focused.
