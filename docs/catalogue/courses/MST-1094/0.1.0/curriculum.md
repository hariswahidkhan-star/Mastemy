## Sample items (original, draft, unreviewed)

**MST-1094-Q0001** (single-answer, Select ONE) In product discovery, what should a manager understand clearly before committing to a solution?

- A. The user's underlying problem and its importance **(key)**  
  _Rationale:_ Correct: discovery validates the problem before investing in a solution.
- B. The exact UI colour scheme  
  _Rationale:_ Visual detail comes far later than problem validation.
- C. The release date announced to executives  
  _Rationale:_ A date is not a substitute for understanding the problem.
- D. The competitor's internal roadmap  
  _Rationale:_ That is rarely knowable and not the discovery goal.

**MST-1094-Q0002** (single-answer, Select ONE) A good acceptance criterion on a user story is one that is:

- A. Testable, so you can objectively tell when the story is done **(key)**  
  _Rationale:_ Correct: acceptance criteria define done in a verifiable way.
- B. Deliberately vague to allow flexibility  
  _Rationale:_ Vague criteria make done ambiguous.
- C. A long technical design document  
  _Rationale:_ Acceptance criteria state outcomes, not full designs.
- D. Only known after the feature ships  
  _Rationale:_ Criteria should be agreed before building.

**MST-1094-Q0003** (multiple-answer, Select TWO) Which TWO statements about product prioritisation are correct? (Select TWO)

- A. A framework helps compare items on consistent factors such as value and effort **(key)**  
  _Rationale:_ Correct: a prioritisation framework brings consistency to trade-off decisions.
- B. Prioritisation should connect back to product strategy and goals **(key)**  
  _Rationale:_ Correct: priorities should serve the chosen strategy.
- C. The loudest stakeholder's request should always win  
  _Rationale:_ Volume is not a sound prioritisation criterion.
- D. Everything on the roadmap should be marked top priority  
  _Rationale:_ If everything is top priority, nothing is.
