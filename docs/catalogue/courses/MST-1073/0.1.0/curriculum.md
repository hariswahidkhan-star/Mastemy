1. Problem-solving mindset and framing
2. Defining the problem precisely
3. Structuring with issue trees and hypotheses

5. Gathering and analysing evidence
6. Generating and evaluating options
7. Decision-making and recommendation

- Does not assess: Knowledge-practice forms use MCQ/MR only; real behavioural performance, live stakeholder interaction and delivery are not assessed in this format.

## Sample items (original, draft, unreviewed)

**MST-1073-Q0001** (single-answer, Select ONE) Why write a precise problem statement before generating solutions?

- A. It focuses analysis on the real problem and prevents solving the wrong thing **(key)**  
  _Rationale:_ Correct: a sharp problem statement aligns effort on the actual issue and its success criteria.
- B. It guarantees the first solution considered will be correct  
  _Rationale:_ A statement frames the problem; it does not guarantee a first-try solution.
- C. It removes any need to gather evidence  
  _Rationale:_ Evidence gathering is still required after framing.
- D. It is only useful for documentation after the fact  
  _Rationale:_ The statement guides the whole analysis, not just documentation.

**MST-1073-Q0002** (multiple-answer, Select ALL that apply) Which statements about structuring a problem with an issue tree are correct? (Select TWO)

- A. Branches should be mutually exclusive and collectively exhaustive (MECE) **(key)**  
  _Rationale:_ Correct: MECE branches avoid overlap and gaps, making the analysis complete and clean.
- B. Each branch can be turned into a testable hypothesis **(key)**  
  _Rationale:_ Correct: issue-tree branches translate into hypotheses that evidence can confirm or reject.
- C. Overlapping branches make the analysis clearer  
  _Rationale:_ Overlap causes double-counting and confusion; MECE avoids it.
- D. An issue tree should list only the solution, not the drivers  
  _Rationale:_ An issue tree decomposes drivers of the problem, not just a chosen solution.

**MST-1073-Q0003** (single-answer, Select ONE) A team fixes the first cause they find, but the problem recurs. What technique most directly addresses this?

- A. Five whys, to keep asking why past the first cause until the root cause is reached **(key)**  
  _Rationale:_ Correct: five whys drives past surface causes to the underlying root cause.
- B. Choosing the first option generated to save time  
  _Rationale:_ That is a cause of the problem, not a remedy.
- C. Skipping evidence gathering to move faster  
  _Rationale:_ Skipping evidence makes recurrence more likely, not less.
- D. Broadening the problem statement until it is vague  
  _Rationale:_ Vagueness hinders root-cause analysis.
