## Learning outcomes

1. Explain Agile values and the empirical basis of Scrum
2. Describe Scrum accountabilities and team design
3. Run the Scrum events to inspect and adapt
4. Manage Scrum artifacts and their commitments

## What this course assesses / does not assess

- Assesses: knowledge and applied reasoning on every in-scope outcome, using single-answer MCQ and multiple-answer selection only.
- Does not assess: Assesses knowledge and applied reasoning through selection items; does not assess hands-on performance.

## Integrative case

A team new to Scrum is treating it as a status-reporting ritual. Design the team's accountabilities, set up the events to actually inspect and adapt, write a Definition of Done and refine a backlog, then explain to a sceptical manager how empiricism will improve delivery.

## Sample items (original, draft, unreviewed)

**MST-1743-Q0001** (single-answer, Select ONE) What is the purpose of the daily scrum?

- A. For the Developers to inspect progress toward the sprint goal and adapt their plan **(key)**  
  _Rationale:_ Correct: it is the Developers' planning event for the day.
- B. For the Scrum Master to collect status for management  
  _Rationale:_ It is not a status report to a manager.
- C. For the Product Owner to assign tasks  
  _Rationale:_ Developers self-manage; tasks are not assigned top-down.
- D. To formally approve the increment  
  _Rationale:_ Approval of the increment is not the daily scrum's purpose.

**MST-1743-Q0002** (multiple-answer, Select TWO) Which TWO are accountabilities in the Scrum framework? (Select TWO.)

- A. Product Owner **(key)**  
  _Rationale:_ Correct: the Product Owner is a Scrum accountability.
- B. Scrum Master **(key)**  
  _Rationale:_ Correct: the Scrum Master is a Scrum accountability.
- C. Project Manager  
  _Rationale:_ Scrum does not define a Project Manager accountability.
- D. Steering Committee  
  _Rationale:_ A steering committee is not part of Scrum.

**MST-1743-Q0003** (single-answer, Select ONE) A team marks items 'done' that still need separate testing before release. What does this violate?

- A. The Definition of Done, which should mean potentially releasable **(key)**  
  _Rationale:_ Correct: Done should mean the increment is potentially releasable.
- B. The sprint length  
  _Rationale:_ Sprint length is unrelated to this problem.
- C. The daily scrum timebox  
  _Rationale:_ The timebox is not the issue here.
- D. The product vision  
  _Rationale:_ The vision is not what 'done' enforces.
