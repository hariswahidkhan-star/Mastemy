## Learning outcomes

1. Why agile exists
2. Iterative, incremental delivery
3. Backlogs, value and prioritisation
4. Common frameworks and roles
5. Improving and scaling sensibly

## What this course assesses / does not assess

- Assesses: knowledge and applied reasoning on every in-scope outcome, using single-answer MCQ and multiple-answer selection only.
- Does not assess: Selection items cannot demonstrate running a real agile team; practice comes through instructor-facilitated simulations.

## Integrative case

A team is drowning in a 40-item wish list delivered as one big release every six months. Reframe the work the agile way: form a prioritised backlog, slice work into increments, run short iterations with reviews and retrospectives, and show how feedback changes the next iteration.

## Sample items (original, draft, unreviewed)

**MST-1742-Q0001** (single-answer, Select ONE) Why does delivering work in small, frequent increments reduce project risk?

- A. Feedback arrives sooner, so wrong assumptions are caught early **(key)**  
  _Rationale:_ Correct: short feedback loops surface problems before they compound.
- B. It removes the need to prioritise  
  _Rationale:_ Increments still require prioritisation of what to build first.
- C. It guarantees the project finishes faster  
  _Rationale:_ It reduces risk and enables adaptation, but does not guarantee speed.
- D. It means documentation is never needed  
  _Rationale:_ Agile values working output but does not forbid documentation.

**MST-1742-Q0002** (multiple-answer, Select ALL that apply) Which statements about a product backlog are correct? (Select TWO)

- A. It is ordered, typically with the highest-value items near the top **(key)**  
  _Rationale:_ Correct: a backlog is prioritised so the most valuable work is done first.
- B. It can change as the team learns more **(key)**  
  _Rationale:_ Correct: the backlog is refined and reordered over time.
- C. It must be fully fixed before any work starts  
  _Rationale:_ Agile expects the backlog to evolve, not be frozen up front.
- D. Items are always worked in the order they were requested  
  _Rationale:_ Order is by value and risk, not request sequence.

**MST-1742-Q0003** (single-answer, Select ONE) A team holds all the Scrum ceremonies but never changes anything based on the retrospective. What anti-pattern is this?

- A. Agile in name only - practising ceremonies without inspect-and-adapt **(key)**  
  _Rationale:_ Correct: following rituals without acting on learning is 'agile in name only'.
- B. Over-prioritising the backlog  
  _Rationale:_ The issue is failing to improve, not prioritisation.
- C. Delivering increments too frequently  
  _Rationale:_ Frequent delivery is desirable; the gap is not acting on retrospectives.
- D. Having too much psychological safety  
  _Rationale:_ Safety is not the problem described here.
