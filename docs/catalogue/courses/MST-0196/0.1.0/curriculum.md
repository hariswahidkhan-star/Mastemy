## Learning outcomes

1. Explain version control, Git and GitHub fundamentals and the GitHub Flow
2. Work with repositories, collaboration tools and modern development practices including Actions, Copilot and Codespaces
3. Manage projects, and describe GitHub privacy, security, administration and community features

## Sample items (original, draft, unreviewed)

**MST-0196-Q0001** (single-answer, Select ONE) A learner asks what distinguishes Git from GitHub. Which statement is accurate?

- A. Git is a distributed version-control system; GitHub is a hosting and collaboration platform built around Git **(key)**  
  _Rationale:_ Correct: Git is the version-control tool, while GitHub hosts Git repositories and adds collaboration features.
- B. Git and GitHub are the same product with different names  
  _Rationale:_ They are distinct: one is the tool, the other is a hosting platform.
- C. GitHub is a version-control system and Git is a website  
  _Rationale:_ This reverses the roles; Git is the version-control system.
- D. Git only works inside GitHub  
  _Rationale:_ Git is independent of GitHub and works with many hosts or none.

**MST-0196-Q0002** (single-answer, Select ONE) Which file conventionally tells contributors how to report vulnerabilities in a GitHub repository?

- A. SECURITY.md **(key)**  
  _Rationale:_ Correct: SECURITY.md documents the repository's security policy and how to report vulnerabilities.
- B. README.md  
  _Rationale:_ README introduces the project but is not the security-policy file.
- C. CODEOWNERS  
  _Rationale:_ CODEOWNERS assigns review ownership of paths, not vulnerability reporting.
- D. LICENSE  
  _Rationale:_ LICENSE states usage rights, not security reporting.

**MST-0196-Q0003** (multiple-answer, Select TWO) Select TWO GitHub features used to collaborate on and track work within a repository. (Select TWO.)

- A. Issues **(key)**  
  _Rationale:_ Correct: issues track bugs, tasks and discussions of work.
- B. Pull requests **(key)**  
  _Rationale:_ Correct: pull requests propose and review changes for collaboration.
- C. Codespaces billing tier  
  _Rationale:_ A billing tier is an account setting, not a collaboration-and-tracking feature.
- D. A commit SHA  
  _Rationale:_ A commit SHA identifies a commit; it is not itself a collaboration feature.
- E. The .gitignore syntax  
  _Rationale:_ .gitignore controls which files Git tracks; it is not a work-tracking feature.
