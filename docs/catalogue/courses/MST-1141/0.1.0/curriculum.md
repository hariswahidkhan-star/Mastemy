## Learning outcomes

1. Explain the project lifecycle and governance roles
2. Define scope and build a work breakdown structure
3. Build schedules and manage the critical path
4. Estimate and control cost and budget
5. Manage risk, issues and quality
6. Manage stakeholders and communication
7. Lead teams and manage change
8. Compare predictive and agile delivery approaches

## What this course assesses / does not assess

- Assesses: knowledge and applied reasoning on every in-scope outcome, using single-answer MCQ and multiple-answer selection only.
- Does not assess: Assesses knowledge and applied reasoning through selection items; does not assess hands-on performance.

## Integrative case

A company is launching a new customer portal with a fixed deadline and an uncertain feature set. The project manager must define scope and a WBS, build a schedule with a critical path, plan cost and risk, map stakeholders, and recommend predictive, agile or hybrid delivery, then defend the plan to the steering committee.

## Sample items (original, draft, unreviewed)

**MST-1141-Q0001** (single-answer, Select ONE) The critical path of a project is:

- A. The longest sequence of dependent tasks, determining the shortest project duration **(key)**  
  _Rationale:_ Correct: the critical path sets the minimum time and has zero float.
- B. The sequence of the most expensive tasks  
  _Rationale:_ Cost does not define the critical path.
- C. Any path with the most tasks  
  _Rationale:_ It is about duration of dependencies, not task count.
- D. The list of tasks assigned to the project manager  
  _Rationale:_ Ownership does not define the critical path.

**MST-1141-Q0002** (multiple-answer, Select TWO) Which TWO belong in a risk register entry? (Select TWO.)

- A. A risk owner responsible for the response **(key)**  
  _Rationale:_ Correct: each risk needs an accountable owner.
- B. A planned response or mitigation **(key)**  
  _Rationale:_ Correct: a response is part of managing the risk.
- C. The project's brand colours  
  _Rationale:_ Irrelevant to risk management.
- D. The CEO's personal phone number  
  _Rationale:_ Not a risk-register field.

**MST-1141-Q0003** (single-answer, Select ONE) A WBS is best described as:

- A. A hierarchical decomposition of the project's deliverables and work **(key)**  
  _Rationale:_ Correct: the WBS organises scope into manageable components.
- B. A time-ordered schedule with dates  
  _Rationale:_ That is the schedule, not the WBS.
- C. A list of project risks  
  _Rationale:_ That is the risk register.
- D. The project's communication plan  
  _Rationale:_ Different artefact entirely.
