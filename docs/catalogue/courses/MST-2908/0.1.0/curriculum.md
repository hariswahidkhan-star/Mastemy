## Learning outcomes

1. Scope a small, achievable AI or data project
2. Choose and prepare suitable data for the project
3. Build or configure a simple model or AI-powered feature
4. Evaluate the project honestly against its goal
5. Consider ethics, privacy and limitations of the project
6. Document and present the project and its results

## What this course assesses / does not assess

- Assesses: knowledge and applied reasoning on every in-scope outcome, using single-answer MCQ and multiple-answer selection only.
- Does not assess: Assesses knowledge and applied reasoning through selection items; does not assess hands-on performance.

## Integrative case

Over several sessions, learners build a small end-to-end AI project (such as a sentiment classifier for film reviews): they scope a realistic goal, prepare data, build and evaluate a simple model honestly on new examples, address privacy and limitations, and present documented results.

## Sample items (original, draft, unreviewed)

**MST-2908-Q0001** (single-answer, Select ONE) Why is it important to scope an AI project to something small and achievable?

- A. A focused goal can be completed, tested and evaluated honestly within the time and data available **(key)**  
  _Rationale:_ Correct: realistic scope makes a project finishable and assessable.
- B. Small projects are the only ones that use computers  
  _Rationale:_ Projects of any size use computers; scope is about feasibility.
- C. A vague, huge goal is always more impressive  
  _Rationale:_ Unrealistic scope usually leads to unfinished, untested work.
- D. Scoping has no effect on the outcome  
  _Rationale:_ Scope strongly affects whether the project succeeds.

**MST-2908-Q0002** (multiple-answer, Select TWO) Which TWO practices make an AI project honest and responsible? (Select TWO.)

- A. Evaluating it on new data, not just the data used to build it **(key)**  
  _Rationale:_ Correct: testing on new examples gives an honest result.
- B. Stating the project's limitations clearly **(key)**  
  _Rationale:_ Correct: being honest about limits is responsible.
- C. Only showing the one example where it worked  
  _Rationale:_ Cherry-picking hides the true performance.
- D. Using people's private data without their consent  
  _Rationale:_ Using private data without consent is unethical.

**MST-2908-Q0003** (single-answer, Select ONE) Your project worked perfectly in one demo. What is the most honest next step before claiming success?

- A. Test it on several new, unseen examples and report how it really performs **(key)**  
  _Rationale:_ Correct: a single successful demo is not proof of reliability.
- B. Declare it finished and perfect  
  _Rationale:_ One demo does not prove reliability.
- C. Hide any examples where it fails  
  _Rationale:_ Honest evaluation reports failures too.
- D. Never test it again  
  _Rationale:_ Further testing on new data is exactly what is needed.
